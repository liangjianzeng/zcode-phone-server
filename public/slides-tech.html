总体架构02 / 09

四层链路与四条基础事实

所有设计决定由 F1–F4 推导

F1 会话库共享

部件粒度实时落盘 → 任意进程可读他人回合进度（轮询跟随的依据）

F2 SSE 进程内

引擎只推自己执行的回合 → 桌面驱动回合只能轮询存储

F3 凭据共享

credentials.json（aes-256-gcm）→ 桥解密桌面登录态

F4 存活边界

未落库会话重启即失 → 存在性以共享库为权威源

SSE 枢纽04 / 09

重放环、例外与合帧

每会话 subs + ring ≤1000 + busy 状态

60ms合帧窗口
数千→数十长回复帧量
0顺序重排

事件分类

常规事件：进重放环（断线按 afterSeq 续传）+ 直播订阅者；model.streaming：只直播不进环（百余 chunk 会挤占环且重放语义不对）；ui/reset：桥注入事件与服务重启信号。

delta 合帧（严格 FIFO）

model.streaming / part.delta 相邻同键 chunk 合并成一帧；只允许与队尾待发 delta 同键合并，其余事件先冲刷再入队——顺序绝不重排。合并帧携带首个 chunk 的 seq，重连重放语义不变。

key = 助手消息id+kind ｜ 消息id+partId+field

页面自更新

index.html 内容 md5 前 8 位作为构建指纹，经 /api/state 下发；页面轮询比对自动 reload——改页面无需重启服务。

防抖两道纪律

renderTextPart 内容未变（pe.raw 比对）直接跳过整段重建；操作行只在持有者变化且为最新消息时迁移——轮询高频入口零 DOM 压力。

问题档案 · 21 条全记录08 / 09

踩坑精华：根因与修复

现象 → 根因 → 修复，每条都实测验证过

#8 会话历史串台

openSession 竞态 + 排队错投 + 旧流泄漏 + boot 漂移 → 代际守卫/绑定/守卫/优先级四道防线。

#9 永久转圈

SSE 断流丢 turn.completed → 存储事实源自愈：finished + 静默 30s 强制复位并补绘。

#14 桌面列表幽灵行

标题只写落库层 + 首回合完成才落库 → 未落库不 INSERT，行龄 >30min 清理。

#15/#19 正文与输入重复

token 直播与部件落库双路同画 → 部件通道唯一事实来源 + ownPart 识别用户输入。

#20 页面抖动

轮询无条件整段重建 + 操作行误迁移 → pe.raw 未变跳过、非最新消息不迁移、增长走合帧。

#21 chip 失效（stopPropagation 拦死冒泡桥）→ 已修；验证方法库：SSE 捕获 / 竞态测试 / 存储手术三备份
边界 · 风险 · 仓库09 / 09

已知边界（架构级）

诚实标注，不藏着

  • 桌面驱动回合：无 SSE 事件、updatedAt 不变——秒级轮询跟随，无 token 流
  • model.streaming 不进环：断流重连后断点前文本由落库补齐
  • sqlite 直写（清库）绕过引擎：需备份三件套 + 白名单 + 孤儿清理
  • 双代 App 桥并存：全量升级 v2 后可撤 DOM 哨兵兼容
